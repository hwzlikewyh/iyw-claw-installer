# 安装失败诊断改进

日期：2026-11-11。范围：安装向导，以及相邻 iyw-claw 正式安装器的进程检查错误传递。

## 目标与方案

用户在故障机看到“正式安装器返回错误 2”和“安装文件写入失败”，无法知道失败环节。
向导继续调用已有 NSIS 安装事务；失败时读取本次新增日志，显示原因、处理建议和诊断操作。
只改向导无法补回正式包丢弃的信息，所以同时保留底层原始退出状态和异常文件。

验收标准：

- 能保留安装子进程的真实退出码，以及本次能取得的原始错误。
- 历史日志不作为本次失败证据；未知、未写日志和读取失败均明确说明。
- 失败页提供查看详情、打开日志和复制诊断信息，长文本可滚动和选择。
- 成功页、取消和返回设置重试继续可用，重试保留安装位置。
- 不根据开发机历史日志推断另一台故障机的根因。

## 错误与日志

Windows 启动正式包前记录 installer.log 字节位置，以及独立进程异常日志的修改时间。
退出失败后仅提取新增内容；旧日志被截短时从头读取，正文最多保留末尾 64 KiB。
支持 UTF-8、Windows 当前本地编码，以及带 BOM 的 UTF-16LE 日志。
独立异常日志只有在本次修改后才纳入报告，避免复用上次失败原因。

向导将本次原始内容保存为 formal-installer.log，完整诊断保存为 installer-error.log。
结束时归档到当前用户目录：

```text
%USERPROFILE%\.iyw-claw\logs\installer\yuan-setup-*\
```

归档失败时保留临时目录中的日志；无日志文件时仍能从界面复制已有的诊断。
复制时将当前用户主目录替换成 %USERPROFILE%；这不是任意敏感信息的全面脱敏工具。
诊断包含版本、安装位置、失败阶段、用时、检查项、退出码、建议及本次事件。

正式包保留 nsExec 原始返回值（包括 error、timeout 和非 2 失败），避免统一错误掩盖启动失败。
PowerShell 异常另存 installer-process-control.log，不受 nsExec 输出字符串长度限制。
后台进程失败写入事务错误原因；主进程预检失败也写日志并显示位置。
本轮保持现有进程筛选、终止和目录链接检查规则；尚未取得故障机具体根因。

## 界面与验证

沿用现有深色原生 wxWidgets 窗口和品牌布局。失败卡片展示原因和建议，下面放三个诊断操作。
详情使用只读原生文本控件，支持键盘选择和水平、垂直滚动；不新增弹窗或网页框架。

已完成 Windows Win32 Release 构建，以及向导的隔离原生验证：

- 实际运行仅写测试日志的子程序，验证成功、失败、取消授权和中文空格路径。
- 核对历史日志排除、日志轮换、64 KiB 上限、UTF-16/本地编码、空日志和缺失日志。
- 核对独立异常纳入报告，原始输出和退出码保留，PID 不会被误识别为退出码。
- 原生窗口检查详情展开/收起、长文本、复制与用户目录替换、成功页隐藏诊断入口、重试保留路径。
- 原生截图检查失败页及详情页，见 diagnostics-failure.png 与 diagnostics-details.png。
