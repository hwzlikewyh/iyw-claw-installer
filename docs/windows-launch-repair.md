# 2026-11-18：更新后主程序无法启动

## 本机复现与修复

本机实际安装目录是 `D:\software\原助理`，不是另一张截图中的 `D:\原助理`。北京时间 10:03:33，AppXDeploymentServer 事件 404/638 记录 `0x80073D02`，占用者为旧版 `IywAssistant.Desktop!Share.Hub`。主程序已是 0.1.353，而当前用户的 0.1.352.0 身份包状态为 `Modified, NeedsRemediation`。主程序和 MSIX 的 Authenticode 均有效。

同一安装另有一条独立错误：安装器用 32 位进程的 `Sysnative` 路径作为 64 位 PowerShell 的工作目录，注册脚本在启动身份探针时报目录无效。用无副作用的子进程复现了 Win32 错误 267。两种失败原来都未阻止安装器显示完成。

- 遇到签名配置声明 `receiver=main` 时，先处理缺失、损坏或版本不符的系统身份，再运行载荷随附的注册和身份校验脚本。工作目录显式设为 `native-share`，仅该子进程使用 Windows PowerShell 自身的模块目录。
- 注册只要求 Windows 关闭目标包的占用，不关闭依赖包。替换应用目录时，向当前用户、安装目录匹配的进程发送关闭请求；共享 1.5 秒宽限后结束仍占用者。旧客户端退出前的身份校验和就绪握手不变。
- 在支持外部身份包的系统上，必需身份注册失败不显示成功。可单独查看 `native-share-register.log.stderr`。非主程序的历史分享入口仍按可选处理。
- 本机修复后回读为 `0.1.353.0 / Ok`；`iyw-claw.exe --native-share-registration-check` 返回 0，原助理正常重启且有可见窗口。未操作另一台机器上的截图路径。

## 更新耗时与流量

- 本机 09:36 的三次手动更新都被旧客户端以 `Active tasks must finish before updating` 拒绝，未启动向导。另一条静默更新记录在 09:57:35 复用已验签缓存，10:02:42 才收到向导就绪。两者不是同一事件；该记录没有逐项耗时，不能把这 307 秒全算作下载、文件占用或某个组件。
- 对本次 Windows x64 稳定查询实际选中的 0.1.350 NSIS、载荷、向导发起单字节请求：网关响应 `302`，声明的响应体长度均为 0；第二跳 `vol-ai.iywtu.com` 返回 `206`。该域名的 CNAME 指向火山 TOS。0.1.353 计划返回的七个环境组件直接访问同一对象域名，返回的范围均为一个字节。
- 用户下载和发布验签不能混算。Fusion 的 `CompleteArtifactUpload` 没有在直传后再上传一次，但会从 TOS 读取整个对象校验摘要及签名。0.1.353 发布日志中九个制品共 1,966,662,169 字节；按每个成功完整校验一次，相当于约 1.97 GB 流入，不是每次用户安装的出流量。此为按文件大小计算，不是生产带宽监控。归因峰值需对齐当时 Fusion 的接收/发送字节、网关按路由的响应字节、发布完成事件与 TOS 访问记录。
