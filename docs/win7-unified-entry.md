系统组件返回 3010 或 1641 时，向导登记当前账户的一次性续装任务，尽量提前下载并验证选定主包及必需组件，再弹出“立即重启 / 稍后重启”，默认稍后。下次登录恢复原安装位置和已选版本，重新检查系统与签名，完成后启动原助理。
预取失败时余下工作留到登录后完成。续装记录只保存安装位置和所需发布元数据。系统源缺失属于安装失败，需根据同一时段的 `CBS.log` 进一步诊断。

## 验收标准

1. Windows 7 SP1 x64/x86 新装和新客户端更新均先进入统一向导，按原生架构选择专用应用包。
2. 已有 PowerShell 5.1 与 .NET 4.5.2 直接复用；缺少时由向导校验并安装微软组件。
3. 系统组件、应用包准备完成才通知应用退出；需要重启时保留旧应用和下载缓存，不强制重启。
4. 旧客户端仍取得原 NSIS 更新字段；统一向导支持显式 NSIS 和历史省略包类型的更新参数。
5. 普通 Windows x64 继续直接部署载荷；Win7 内部复用静默 NSIS，不展示另一套安装界面。

## 边界与官方依据

只下载所选版本的在线包，不内嵌应用，不修改 runtime/config/data。
历史发布无向导元数据时保留原更新路径。Win7 不使用其他系统的应用载荷。
微软 WMF 5.1 官方安装文档要求 .NET 4.5.2 或以上（Release 379893）；
原阈值 378389 对应 .NET 4.5，需要纠正。安装要求重启时暂停，重启后重新运行复用缓存。

原解压库默认 `WINDOWS_VERSION=WIN10`，改用上游支持的 `WINDOWS_VERSION=WIN7`。
另确认 MSVC 14.51 静态 STL 的 filesystem 直接引用 Win7 不存在的 `CreateFile2`，
沿用现有时钟导入兼容方式，将该入口映射为等价 `CreateFileW` 调用；保留属性、
文件标志、安全属性、共享方式和模板句柄。打包时禁止出现 `CreateFile2` 系统导入。
